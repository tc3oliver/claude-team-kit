# CTK work contract (internal; becomes docs/ARCHITECTURE.md)

Read this first. Each workstream owns its files and must not edit another's.
Shared, already-written, **do not change without telling the lead**:
`plugin/ctk/shared/{policy,stats}.ts`, `src/core/{paths,fsx,jsonx,schema,profilestore}.ts`, `src/cli/context.ts`.

## Conventions

- TypeScript, `erasableSyntaxOnly` (no enums, no parameter properties, no namespaces). Relative imports use the `.ts` extension. Node >= 20 at runtime (compiled), tests run `.ts` directly on Node >= 22.18.
- Only runtime dependency: `zod`. Prefer `node:` built-ins (`parseArgs`, `child_process`, `fs`, `crypto`).
- Tests: `node:test` + `node:assert/strict`, files `test/**/*.test.ts`. Deterministic, no network, no real `~/.claude`. Every test uses a temp `configDir` (`fs.mkdtempSync(join(os.tmpdir(), 'ctk-'))`) and cleans up.
- Cross-platform: `path.join`, never hardcode `/`; paths written into settings use `toPosix`. No POSIX-only shell commands. Spawn with `execFile`/`spawn` and an argv array, `shell: false` (on win32 `claude` may be `claude.exe` or `claude.cmd`; `.cmd` needs `shell: true` with quoted args: isolate that in one helper).
- Never read, print, log or copy credentials. Never read `~/.claude.json` content (onboarding detection = file existence only). Never touch the real `~/.claude`: tests and manual probes use a scratch `CLAUDE_CONFIG_DIR`.
- Never `git push`. No `Co-Authored-By` or tool attribution anywhere. Do not commit; the lead commits.
- No TODO stubs, no `test.skip`/`.only`. If something is impossible, say so in your report and degrade explicitly.
- Keep it small. No abstraction layer without a second caller.

  .claude-plugin/plugin.json

  shared/policy.ts, shared/stats.ts                     (lead)

src/cli/{bin,index}.ts, src/cli/commands/*.ts, src/install/**   (WS-D; sync.ts is WS-E)
src/sync/**, src/cli/commands/sync.ts                           (WS-E)

Ids: plugin `ctk`, marketplace `ctk-kit`, plugin id `ctk@ctk-kit` (constants in `src/core/paths.ts`).
Options flow: profile -> `profileToPluginOptions` -> `settings.json` `/pluginConfigs/ctk@ctk-kit` -> `register(on, options)` -> `readOptions`.

## WS-A  plugin mod (`plugin/ctk/hooks`, `plugin/ctk/tests`)

Start from the PoC copies `*.poc` in `plugin/ctk/hooks` and `plugin/ctk/tests` (validated: `agent.spawn` cap, race-safe `inflight` reservation, fail-closed `.catch`, HUD band). Reuse, restructure into small files, delete the `.poc` copies when absorbed. Mod rules enforced by `claude plugin validate`: one unmatched hook per event per module file set as in PoC; `$` only passed to top-level functions of the same file; event names string literals; imports only relative inside the plugin + `claude-code`. Types for this build are generated into `plugin/ctk/.claude-plugin/types/` (gitignored) when you run `claude --plugin-dir plugin/ctk -p "/ctk-stats" ` with `CLAUDE_CONFIG_DIR=<scratch dir>` (works logged-out, no model call); `claude plugin test plugin/ctk` and `claude plugin validate plugin/ctk --strict` need no login either. Read declarations there (`claude-code/index.d.ts`) instead of guessing.

Behaviour:
1. **Hard cap** (keep PoC semantics): only `e.isTeammate === true` spawns are gated; cap = `readOptions(options).maxWorkers`.
2. **Explicit rejection**: the deny text MUST start with `TEAM_CAPACITY_REACHED:` (constant `CAPACITY_CODE`), then `live=N starting=M max=K` and one imperative sentence: do not treat this worker as started; leave its task pending; reuse an idle teammate via SendMessage or wait. Guard failure deny starts with `TEAM_GUARD_FAILED:`.
3. **Accepted spawn is verified, not assumed**: after `next(e)` resolves without `deny`, require `agentId` (and `teammateId` for teammates); if missing treat as not started, do not count it. Record accepted model from the result into stats `workerModels`.
4. **Model routing**: if `e.model` is undefined and `e.subagentType` is one of `AGENT_TYPES`, call `next({ ...e, model: modelFor(opts, role) })`; if `inherit`, pass through unchanged. Never override an explicit `e.model`. Effort: try `turn.step` `next({...e, effort})` only for loops whose `agentId` was spawned by us as a role whose configured effort differs from `DEFAULT_EFFORT` — but the options carry models only, so **do not implement effort override**; state in code comment + report that effort comes from the agent frontmatter.
5. **Status tool** (the lead's way to confirm real state): register a tool `ctk_team_status` via `$.tool.register` that returns JSON `{ live, max, workers:[{name,teammateId,status}], rejected, accepted }` from `$.agent.list()` + counters. Short description (<= 25 words). If registration cannot pass `claude plugin validate`, drop it, say so, and rely on `teammate_id` in the Agent result.
6. **Task counters**: `on('classic.TaskCreated')` / `on('classic.TaskCompleted')` only increment counters and `return next(e)` (read-only; must never block). `tasks: null` until one fires.
7. **HUD band** (`ui.render` AbovePrompt, only if `hudBand`): one line, e.g. `team 1 busy · 2 idle · 1 done / cap 3 · tasks 2/5 · rejected 1 · models haiku×1 sonnet×2 · $0.42 · 12m`. Missing figures render as `–`, never a guess; segments with no data (tasks null) are omitted. Must fit 80 columns (truncate with `…`; test). Yields to `hasSurvey`. Refresh on `session.start`, `session.measure`, `turn.complete`, and after each spawn decision. No network, no model call, no transcript scan.
8. **Stats file** (only if `recordStats`): after state changes (debounced to at most one write per 2 s) write `StatsRecord` JSON to `<config>/ctk/stats/<safeSessionId>.json` via `$.fs.write`. Config dir = `$.env.get('CLAUDE_CONFIG_DIR')` else `<HOME or USERPROFILE>/.claude`. Wrap in try/catch: a stats failure never affects a spawn or the HUD. Only counters/percentages/cost/model names; no prompts, no paths, no ids beyond the session id.
9. **Command** `ctk-stats`: returns the same multi-line summary `ctk stats` prints for this session (measured vs counted, labelled). No per-worker cost is shown; say "per-worker cost: not available from Claude Code".
10. **Capability detection**: every host call wrapped so an unsupported API degrades (HUD omitted, cap still enforced fail-closed). Cap fail-closed on `agent.list` failure stays.

Tests (`claude plugin test`): keep the 15 cap cases + 6 HUD cases green after the refactor; add: deny text starts with the code; accepted-without-agentId not counted; routing (alias applied, explicit model kept, non-CTK agent untouched, `inherit` untouched); task counters via synthetic `classic.*` events; stats file content via stubbed `$.fs`; 80-col truncation; band hidden when `hudBand=false`; status tool output. Run `claude plugin validate plugin/ctk --strict`; it must pass and the `calls:` list should be small and only read-only host APIs plus `fs.write` (stats) and `tool.register`.

## WS-B  skills, agents, manifests (`plugin/ctk/skills`, `agents`, `.claude-plugin/plugin.json`, repo-root `.claude-plugin/marketplace.json`)

Always-on plugin context must stay **< 500 tokens** (target < 250); check with `CLAUDE_CONFIG_DIR=<scratch> claude plugin marketplace add <repo> && claude plugin install ctk@ctk-kit` then `claude plugin details ctk@ctk-kit` (scratch config dir only). Descriptions are the always-on cost: <= 25 words each.

- `plugin.json`: name `ctk`, version `0.1.0`, `types: ./types/index.d.ts` only if a types file exists, `userConfig` for exactly the keys in `PolicyOptions` (`maxWorkers` number min 1 max 12, four model strings, two booleans) with defaults from `DEFAULT_OPTIONS`, `license: MIT`, author, repository placeholder `https://github.com/OWNER/claude-team-kit` is NOT allowed (use no `repository`/`homepage` field until the owner is known).
- Marketplace `ctk-kit`, one plugin `ctk` with `source: ./plugin/ctk`. Validate with `claude plugin validate . --strict` and `claude plugin validate plugin/ctk --strict`.
- **Agents** (frontmatter per official fields): `explorer` (model haiku, effort medium, read-only tools), `implementer` (sonnet, medium), `reviewer` (sonnet, medium, read-only), `high-risk-reviewer` (opus, effort high, read-only). `model`/`effort` must equal `DEFAULT_OPTIONS`/`DEFAULT_EFFORT` (contract test). Bodies <= 12 lines each. Do not use `hooks`, `mcpServers`, `permissionMode` (ignored for plugin agents). Agent types as reported: `ctk:explorer` etc. (`AGENT_TYPES`).
- **Skills** (Progressive Disclosure: SKILL.md <= 60 lines, details in `references/*.md` read on demand; design rules: context pointers instead of pasted content, one source of truth, no restating native tool docs):
  - `team` (`disable-model-invocation: true`, `argument-hint: "<goal>"`): default single agent unless the user asked for a team or the work splits into >= 2 independent slices; vertical slices each independently verifiable; native `TaskCreate` with `addBlockedBy`; ready frontier = pending tasks with no open blockers; spawn <= the cap using `Agent` with `name` and `subagent_type` `ctk:implementer`/`ctk:explorer`; file-scope per worker, `isolation: worktree` when scopes can overlap; hand workers **context pointers** (spec path, task id, file list, commit sha), never pasted contents; lead integrates, verifies, shuts workers down (SendMessage shutdown request) so capacity frees. **Spawn confirmation protocol** (critical): a spawn counts only if the Agent result carries a `teammate_id`/agent id and `ctk_team_status` (if present) lists the worker; a result containing `TEAM_CAPACITY_REACHED` or `TEAM_GUARD_FAILED`, or a row that merely shows "Done", is NOT started: do not set an owner, keep the task `pending`, re-offer it when a slot frees. No fixed plan/PRD/execute/review/fix pipeline. Model routing is by role, no LLM router, no Haiku planner for simple tasks.
  - `review`: risk-based. Decide risk from the diff (auth, money, data migration, concurrency, public API, security => high). Axis 1 standards (project rules, correctness, simplicity), axis 2 spec (does it do what the ticket says). Low risk: self-review checklist only. Medium: `ctk:reviewer`. High: `ctk:high-risk-reviewer`. Findings must cite file:line and a failing scenario; no style nitpicks the linter owns.
  - `debug`: Reproduce (write the failing command/test first) -> Minimize -> Diagnose (hypotheses, one probe each) -> Fix -> Regression test. Stop and ask after three failed hypotheses.
  - Write for agents: imperative, no filler, no duplicated platform docs. Each `references/` file <= 80 lines.
- `test/contract.test.ts`: plugin.json userConfig keys/defaults == `DEFAULT_OPTIONS`; agent frontmatter == defaults; every skill has name+description, SKILL.md <= 60 lines, references exist; descriptions <= 25 words; `team` skill text contains `TEAM_CAPACITY_REACHED`. Add `scripts/measure-context.mjs` that prints char counts and a rough token estimate (chars/4) of all always-on text so CI can assert a budget (< 500 tokens).

## WS-C  statusline fallback (`plugin/ctk/statusline/`)

Single dependency-free ESM file `ctk-statusline.mjs` (it is copied alone to `<config>/ctk/bin/`). Starts from the PoC (`ctk-statusline.mjs.poc`, `test/statusline.test.mjs.poc`). Reads the official stdin JSON only (schema: `model`, `effort.level`, `context_window.used_percentage`, `rate_limits.five_hour/seven_day`, `cost.total_cost_usd`, `cost.total_duration_ms`, `workspace.current_dir`, `workspace.git_worktree`, `worktree.*`). Output one line: `Model effort · ctx 42% · 5h 24% · 7d 61% · $1.23 · 12m · branch*`. Missing values print `–`; effort omitted when absent; never fabricated. Git: read branch by parsing `.git/HEAD` (handle `.git` file `gitdir:` for worktrees; detached => short sha); dirty marker `*` from `git status --porcelain -uno` via `execFileSync('git', [...], { timeout: 250, stdio: ['ignore','pipe','ignore'], cwd })`, any failure/timeout => no marker, no error. Honour `COLUMNS` (truncate with `…` from the git/cost end, never split an ANSI code; plain output by default, no ANSI unless `CTK_COLOR=1`). When Mods are active the team band shows workers/tasks; this line shows no worker data and says nothing about workers. No network, no reads of any file except `.git/HEAD` + the git call, no OAuth, no transcript. Exit 0 and print one line even on garbage/empty stdin. Tests (`node --test`): all PoC cases kept, plus effort, elapsed formatting (`45s`, `12m`, `1h05m`), git branch/detached/worktree via temp repos created with `git init`, dirty marker, COLUMNS truncation, latency < 300 ms avg. Export `render(input, env?)` for tests.

## WS-D  CLI core and installer (`src/cli`, `src/install`, `src/core/{settings,ledger,claude}.ts`)

`bin.ts` (shebang `#!/usr/bin/env node`), `index.ts` router using `util.parseArgs`; global options `--config-dir --profile --device --dry-run --json --yes --help --version`. Commands: `install doctor sync update rollback uninstall stats config`. `sync` is implemented by WS-E as `export async function runSync(argv: string[], ctx: Ctx): Promise<number>` in `src/cli/commands/sync.ts`; the router imports it dynamically (`await import('./commands/sync.ts')`) so the build works before it exists only if you do not statically import it. Output: human text by default, one JSON document with `--json`. Exit codes: `EXIT` in `src/cli/context.ts`.

**Ledger** (`<config>/ctk/ledger.json`, written atomically, schemaVersion 1): `{ ctkVersion, configDir, entries: LedgerEntry[], transactions: Tx[] }`.
`LedgerEntry = { kind:'settings-key', pointer, prior:{absent:true}|{value}, written, owned:boolean } | { kind:'file', path, sha256, priorSha256:string|null } | { kind:'plugin', marketplaceAddedByCtk:boolean, pluginInstalledByCtk:boolean }`. `Tx = { id, op, at, backupId, entryChanges }`.

**Ownership rules** (settings.json is only ever edited by pointer, preserving all other keys and key order; invalid JSON => refuse and exit 1):
- CTK-owned pointers: `/pluginConfigs/ctk@ctk-kit` (plugin options), `/statusLine` (only when absent or already CTK's command), `/env/CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` (only when absent, and `claude.enableAgentTeams`), plus `portable.settings` keys applied by sync (WS-E calls your `applyProfile`). Plugin enablement is done by the `claude plugin` CLI, never by hand-editing `enabledPlugins`.
- Key absent => write, record `prior:{absent:true}`, `owned:true`. Key present and deep-equals desired => record `owned:false` (not ours, never removed). Key present with a different value that CTK did not write => **conflict**: leave it, report it, exit 2. Key we own whose current value != our `written` (user edited since) => treat as user-owned: leave it, report, exit 2.
- A user's existing `statusLine` is never replaced; report that the HUD runs via the mod band only.

**install** [--no-statusline] [--no-enable-teams]: detect platform/WSL (`/proc/version` contains microsoft) and Claude Code version (`claude --version`); require >= 2.1.287 for mods else install skills/agents/statusline only and say mods are unavailable. Steps: plan -> (dry-run prints plan, writes nothing, exit 0) -> backup `settings.json` and Claude's plugin registry files that `claude plugin` will touch (`createBackup`) -> `claude plugin marketplace add <packageRoot>` (skip if `ctk-kit` already registered at that path) -> `claude plugin install ctk@ctk-kit --scope user` (skip if installed) -> copy `plugin/ctk/statusline/ctk-statusline.mjs` to `paths.statusline` -> patch settings -> write ledger. Resolve exact `claude plugin` flags from `claude plugin <cmd> --help` in a **scratch** `CLAUDE_CONFIG_DIR`; all `claude` calls set `CLAUDE_CONFIG_DIR=configDir` in the child env. **Idempotent**: a second run changes no file (assert mtime + content hash unchanged, no new backup, no new transaction). Statusline command: `"<abs node path>" "<abs statusline path>"` with forward slashes, from `process.execPath`.

**uninstall**: reverse owned entries newest-first only where current value still equals `written` (else leave + report); `claude plugin uninstall ctk@ctk-kit`; remove marketplace only if `marketplaceAddedByCtk`; delete `<config>/ctk` except `backups/`. Never touches unowned keys or other plugins. **rollback** [--to <txId>]: undo the latest undoable transaction with the same per-entry safety check; backups are never deleted. **update**: refresh marketplace, `claude plugin update ctk@ctk-kit`, re-copy statusline if the packaged hash changed, re-apply profile; idempotent. Prints a hint for upgrading the npm package. **doctor**: checks (each pass/warn/fail with a one-line fix): Node version, Claude Code version + mods support, WSL, config dir + settings.json parse, plugin installed+enabled, marketplace registered, agent-teams env, statusLine state, onboarding (existence of `.claude.json` only), ledger vs settings consistency, backups restorable (`verifyBackup`), `ctk` skills dir markers. Exit 0 all pass, 2 warnings, 1 failures. **stats**: reads `<config>/ctk/stats/*.json` (`parseStats`), prints per-session and total: accepted/rejected spawns, peak live, worker model distribution, tasks created/completed, last measured cost/context/limits; labels **measured** (Claude Code reported) vs **counted** (CTK counted events); never prints per-worker cost. **config** `get|set|list|unset <dotted.path> [value]` on the user layer, or on the device layer with `--device-layer`; validate via `parseLayer`; then re-apply (`applyProfile`) unless `--no-apply`.

Export for WS-E (in `src/install/apply.ts`): `applyProfile(ctx: Ctx, effective: Profile, opts?: { op: string }): Promise<ApplyResult>` — computes desired settings entries (`pluginConfigs`, `portable.settings` keys, statusLine/env per profile), applies them under the ownership rules in one backed-up transaction, no-op when nothing differs; `ApplyResult = { changed: boolean; conflicts: {pointer:string; reason:string}[]; skipped: string[] }`. Also export `materializeSkills(ctx, names, repoSkillsDir)`: copies `<repo>/skills/<name>/` to `<config>/skills/<name>/` with a `.ctk-managed` marker file; a destination directory without the marker is never touched (conflict). Tests use a stub `claude` (a small node script written to a temp dir, passed as `ctx.claudeBin`) that records argv and mutates a fake registry file — plus one real-binary integration test in a scratch config dir that auto-skips when `claude` is absent.

## WS-E  sync (`src/sync/**`, `src/cli/commands/sync.ts`)

Git-only, no server. Profile repo layout: `ctk-profile.json` `{ "schemaVersion":1, "name":"..." }`, `profiles/<name>.json` (a `ProfileLayer`), `skills/<name>/**`. Local clone: `<config>/ctk/sync/repo` (`ctx.paths.syncRepo`); config `<config>/ctk/sync/config.json` `{ remote, branch }`. Use `execFile('git', args)` with `GIT_TERMINAL_PROMPT=0`; no credentials handled by CTK (git's own helpers).

Subcommands: `sync init --remote <url|path> [--branch main]` (clone or init an empty repo; refuse to overwrite a different existing remote), `sync status`, `sync pull` (default for bare `sync`), `sync publish [-m msg]`, `sync resolve <pointer> ours|theirs`. All honour `--dry-run`. Neither pull nor publish ever force-pushes or rewrites history.

**Three-way merge** (`merge3.ts`, pure): inputs `base`, `ours`, `theirs` as flattened maps (`flatten` from jsonx; skills as `skills/<name>/<relpath>` -> content hash). Per key: ours==theirs -> take it; ours==base -> theirs; theirs==base -> ours; else **conflict** (value left as ours). Deleted vs modified is a conflict. Output `{ merged, conflicts[{key,base,ours,theirs}], applied[], unchanged }`. `base` = `<config>/ctk/sync/base.json` (last synced snapshot). Conflicts are written to `ctx.paths.syncConflicts`, never silently resolved; exit 2; `sync resolve` settles one and clears it.

**pull**: `git fetch` + fast-forward only (`git merge --ff-only`; if diverged, report and exit 2 without changing the clone) -> read `profiles/<ctx.profile>.json` (theirs) and local `profile.json` (ours) -> merge3 -> validate with `parseLayer` -> write merged user layer + skills dir plan -> call `applyProfile` (from WS-D `src/install/apply.ts`; inject it as a parameter so tests stub it) with `loadEffective` -> update `base.json` only for keys that merged cleanly. **publish**: pull first; if conflicts exist abort; secrets-scan everything that would be committed; write `profiles/<name>.json` from the local user layer (device layer is NEVER published) and managed skills; `git add` only those paths; commit (message default `ctk: update profile <name> from <device>`; **no co-author/tool trailers**); `git push` to the configured remote/branch. Dry-run prints the file list and the scan result.

**Whitelist**: only `ProfileLayer` fields (which already restrict `portable.settings` to `PORTABLE_SETTINGS_KEYS`), and `skills/<name>/**` for names listed in the profile `skills`. Anything else in the repo is ignored on pull and refused on publish. Skill files: allow text only (`.md .txt .json .yaml .yml .mjs .js .ts .sh`), max 256 KiB each, 100 files per skill, no symlinks, no path traversal (`..`, absolute, drive letters), no executables bit reliance.

**Secrets scanner** (`secrets.ts`, pure, no network): patterns for Anthropic/OpenAI/GitHub/AWS/Google/Slack/Stripe tokens, private key blocks, JWTs, `Authorization: Bearer`, URLs with `user:pass@`, generic `(api[_-]?key|secret|token|password)\s*[:=]\s*['"]?[A-Za-z0-9/+_\-]{16,}`, plus high-entropy (Shannon > 4.2, length >= 24) base64/hex strings in values; deny-listed key names anywhere in JSON (`apiKey`, `api_key`, `token`, `secret`, `password`, `oauth*`, `credentials`, `authorization`, `refreshToken`, `apiKeyHelper`, `env`). Findings report file + line + rule id + a **redacted** 4-char preview, never the secret. Publish refuses on any finding; there is no override flag. Pull also scans incoming content and refuses to apply files with findings.

Tests (use local bare repos as the "remote" in temp dirs): init/pull/publish round trip across two simulated devices; fast-forward only; every merge3 truth-table row; delete-vs-modify; conflict file written and original untouched; resolve; idempotent pull (second pull: no writes); dry-run writes nothing; device layer never in the repo; secret in a skill and in a profile value blocks publish and the repo is not modified; whitelist/traversal/symlink rejection; scanner true/false positives table (include look-alikes: git SHAs, UUIDs, hashes in lockfile style must NOT be flagged).
